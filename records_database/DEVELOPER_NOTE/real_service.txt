## IDHAR UDHAR — Real Services Stack

### 1. 📱 Real SMS OTP — **MSG91**

**Use:** Customer + Rider login/registration

```text
Flutter
   ↓
NestJS
   ↓
MSG91 OTP API
   ↓
Indian mobile number
   ↓
OTP
   ↓
NestJS verifies
   ↓
JWT Session
```

Important: **OTP verification authority remains our backend**, not Flutter.

For India, DLT entity registration, sender/header and approved SMS templates are required before production SMS delivery. ([MSG91][2])

MSG91 currently publishes India OTP pricing starting around ₹0.25 at 5,000 OTPs and reducing with volume; actual commercial pricing should be confirmed when we create the account. ([MSG91][3])

---

### 2. 🗺️ Google Maps — **Google Routes API**

**Use:**

* Pickup → Drop road distance
* Multi-stop routing
* ETA/duration
* Later rider/customer map features

We already built the backend adapter in Phase 7.

Production:

```text
NestJS
   ↓
Google Routes API
   ↓
Road distance + duration
   ↓
Fare Engine
```

The important part is that **Flutter never decides the final distance/fare**.

### 3. 🔔 Push Notifications — **Firebase Cloud Messaging (FCM)**

**Use:**

* New rider offer
* Rider assigned
* Order status
* Payment notification
* COD warning
* etc.

Architecture:

```text
NestJS Worker
     ↓
FCM
     ↓
Customer/Rider phone
```

Our Phase 6 `PushProvider` architecture is already designed for this, so we don't need to redesign notifications.

### 5. 💳 Online Payment — **Payment Gateway**

This one we should choose carefully.

For India, likely candidates include:

* Razorpay
* Cashfree
* PhonePe Payment Gateway

Architecture:

```text
Customer
   ↓
Flutter
   ↓
Payment Gateway
   ↓
Webhook
   ↓
NestJS
   ↓
PostgreSQL
```

**Webhook is the authority**, not "payment success" returned blindly by Flutter.

I would **not select the provider yet** until we compare fees, settlement, refunds, webhook behavior and our COD/payment model.
