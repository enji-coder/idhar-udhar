## Audit verdict

Production had a **real accept/state machine**, but **no automatic rider dispatch** after confirm, plus **dummy accept paths** in Flutter (rider dashboard + customer Track Delivery / tracking demo).

---

## 1. Current production workflow

```text
Customer create → quote → confirm (fare snapshot)
  → SEARCHING
  → SYSTEM/admin create order_offers → OFFERED
  → Rider accept (atomic) → ASSIGNED
  → EN_ROUTE_PICKUP → ARRIVED_PICKUP → PICKED_UP
  → IN_TRANSIT → NEAR_DROP → DELIVERY_ATTEMPT → DELIVERED
```

Trip **Cashfree is not** required before search today. Cashfree is used for **waiting/receivable** clearance. Summary payment method is UI/local; confirm body is only `fare_quote_id`.

## 3. Root causes

1. Confirm only moved to `SEARCHING`; offers were **admin-only** → customers waited forever unless admin dispatched.  
2. Rider dashboard “accepted” **locally** without `POST /accept`.  
3. Customer UI showed **order UUID** and locally faked post-assign progression.  
4. Mapper did not surface assigned rider display fields from API.

## 7. Payment timing

| Method | Timing |
|--------|--------|
| **Online trip fare** | Selected on summary; **not charged at confirm** in current architecture |
| **Cashfree webhook** | Authoritative for ONLINE intents that the backend creates (e.g. waiting clearance) |
| **COD** | UI/cash plan; rider COD due / suspend rules on accept eligibility |
| **Rider assignment** | After confirm → SEARCHING → offers → accept (no payment gate) |
| **Waiting** | After ARRIVED_PICKUP assessment; Cashfree for receivable |
| **Settlement** | On DELIVERED via existing settlement path |

---

## 8. Rider matching (now)

After confirm → `dispatchOffersForSearchingOrder`:

- Eligible: `ONLINE` + `APPROVED` + active vehicle for order’s `vehicle_category_id` + not COD-suspended + no live order  
- Creates pending `order_offers` + `SEARCHING→OFFERED` (SYSTEM) + `OFFER_NEW` notification  
- Rider accept remains transactional (order+offer locks, one winner)

No GPS radius. No fake auto-accept.

## 12. Remaining blockers

1. Riders need **active `vehicles` row** matching the booked category or SYSTEM dispatch finds nobody.  
2. Idle ONLINE riders still don’t stream GPS (location only on active delivery).  
3. Trip **online payment before search** is not in the order-domain architecture — product decision required.  
4. Offer TTL is lazy (no background expire worker).  
5. Deploy backend for SYSTEM dispatch to hit production.
